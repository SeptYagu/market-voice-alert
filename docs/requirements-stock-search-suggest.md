## 1. 目标与现有实现边界

用户只记得名称、拼音或旧名时，能够找到正确标的并加入监控；已有代码输入、批量添加、刷新、持久化及 K 线预热继续工作。

| 已核对的实现 | 本需求的约束 |
| --- | --- |
| `src/js/views/toolbarView.js` 的 `#code-input` 目前只处理 Enter，按钮同样调用 `onAdd` | 统一键盘、按钮与候选选择规则，避免重复提交 |
| `src/js/app.js` 的 `handleAdd()` 调用 `parseBatchInput()`、`monitorCtrl.addCodes()`，随后渲染、刷新与预热 | 提取可接收规范代码的共享添加入口，不能另写一套持久化流程 |
| `src/js/services/batchExportService.js` 按中英文逗号、普通空格分词，忽略无效项并去重 | 保留语义；换行/Tab 分隔是新增兼容，不可写成已实现 |
| 股票规范代码是 sh/sz/bj 加六位数字；期货由 `parseFutureInput()` 解析，监控列表保存小写符号 | 候选可显示 `RB0`，实际存储及去重用 `rb0`，沿用现有解析器 |
| `/api/cache/futures/contracts` 来自 `PRODUCT_MAP`，只列各品种的 0 连续合约 | 不能称为全部在市月份合约目录，不能排列月份虚构合约 |
| `/api/cache/spot/latest` 是 HTTP 路径，`latest.json` 是服务端缓存文件名 | 浏览器不能请求 `/api/cache/spot/latest.json` |

### 1.1 本期范围

- A 股：沪、深、北当前上市标的，含停牌股。上市名单不能用有报价的股票集合替代。
- 名称：证券简称及历史简称；工商全称、民间昵称不默认纳入，明确维护的别名除外。
- 期货：现有 `PRODUCT_MAP` 的名称、拼音和连续合约联想；完整月份合约代码继续经现有解析器添加。格式合法不等于已验证仍在交易。
- ETF、指数、债券、B 股、港美股名称联想及完整月份合约目录不在本期范围；原解析器可接受的代码继续添加，不得因字典未收录而拒绝。
- 不增加交易、推荐、搜索历史、热度榜或账户同步。

## 2. 查询规范与匹配

### 2.1 标准化与模式判定

1. 查询副本做 Unicode NFKC 标准化、去首尾空白、拉丁字母转小写；显示名称保留原文，不改写成搜索键。
2. **批量优先**：去首尾空白后含中英文逗号，或含内部空白（空格、Tab、换行），进入批量模式；末尾逗号也算，首尾空白不算。
3. 批量模式立即收起候选、取消联想，只解析代码及已有期货别名，不逐项猜股票名称。`600519,未知词,000001` 添加两个有效代码并提示忽略 1 项；全无效保留输入并报错。空 token 不计入反馈。
4. 单项查询从 1 个字符开始，防抖 150 ms；空输入关闭。首版不支持空格分隔拼音音节，`gui zhou` 是批量输入，应使用 `guizhou`。名称索引可消除排版空白，允许 `万科A` 搜到含空格简称。
5. 单项查询最多 64 个 Unicode 字符，超出提示缩短并停止模糊搜索；不限制原有批量路径。
6. 不做编辑距离纠错、乱序、声母/全拼任意混拼或繁简转换。多音字按词语读音建立索引，允许有来源的纠音表，不无界排列多音字。拼音无声调，ü 统一为 v，查询使用相同规则。

### 2.2 必须支持的匹配维度

下表定义固定测试夹具及预期，不宣称示例名称/状态在任意运行日均未变化。生产名称遵循第 4 节时效规则。

| 维度 | 规则 | 必须命中的样例 |
| --- | --- | --- |
| 代码 | 六位数字或带市场前缀代码完全/前缀匹配，保留前导零；带市场前缀不跨市场 | `60051/sh60051` → `sh600519`；`000001` → `sz000001` |
| 中文 | 现名、基础简称、曾用名分别做完全及连续子串匹配 | `茅台` → 贵州茅台 |
| 拼音首字母 | 每字首字母，原有拉丁字母及数字保留；完全及前缀匹配 | `GZMT` → 贵州茅台；`xrgf` → 新锐股份 `sh688257`、新日股份 `sh603787`、雪人集团 `sz002639`（曾用名雪人股份） |
| 连续全拼 | 拼音串连续子串，可从词中开始，也支持未完成音节；不要求整词或音节边界，不做非连续匹配 | `shiyou` → 中国石油、中曼石油、`sz000697`（炼石有色中的“石有”）；`guizh` → 贵州茅台 |
| 曾用名 | 每个旧名建立中文、首字母、全拼键，按规范代码合并 | `雪人股份/xrgf` → 雪人集团；`炼石有色/shiyou` → 炼石航空；`深发展/sfza` → 平安银行（曾用名深发展A） |
| 期货 | 品种中文/拼音/产品代码前缀指向目录中的连续合约；完整合约继续解析，兼容原 nf 格式 | `rb/螺纹钢/lwg` → 螺纹钢连续 `RB0`，存 `rb0`；`RB2610` 直接添加 `rb2610` |

由旧名命中必须展示实际 `曾用名：…`，主名称显示当前可用名称，不能只展示旧名。历史状态名可以作为曾用名检索，但不改变当前状态徽标。缺少真实月份目录时不生成月份前缀候选，完整合约仍可直接添加。

### 2.3 特殊状态名

- 覆盖 `ST/*ST/XD/XR/DR/N/C`，仅在数据源确认的名称前缀位置解析，较长标记优先，允许多个有证据的标记共存。不在词中/词尾全局删除 st/c/n；其他位置状态只接受显式元数据，不臆测后缀。
- 分别保存 `displayName`（如 `XD美的集`）与 `baseName`（如 `美的集团`）。截短名无法靠删除 XD 恢复全名，基础字典或核实别名必须提供完整简称，缺失视为数据缺口。
- 夹具 `*ST西发` 支持 `xf/西发/stxf/*stxf`；夹具 `XD美的集` 加完整基础名支持 `mdjt/美的集团/xdmd`。
- 纯状态查询 st 包含 ST 与 *ST，*st 仅含 *ST；xd/xr/dr/n/c 对股票只查有对应**有效当日状态**的条目，不能把历史名 ST 当今日警示。
- 单字母可同时是期货代码。状态查询合并正常期货代码匹配，`c` 必须保留玉米连续合约，并标明类型。
- 带状态组合查询增加“状态 + 名称片段”分支，同时保留普通名称/拼音分支，避免把 c/n/st 开头的正常拼音误当状态。前一分支需状态与名称同时满足；历史原始名另走旧名规则并标明，不能因此显示过期状态徽标。
- 无状态证据提示“当日状态未更新”；未知不等于无状态，不承诺全部状态名实时可搜。

### 2.4 排序、去重与上限

每个规范代码只保留一项，取最高优先级命中，不累加多个旧名的分数。顺序如下：

1. 完整规范代码/完整可解析期货合约。
2. 当前展示名或基础简称完全匹配。
3. 曾用名中文完全匹配。
4. 代码前缀（含期货产品代码）。
5. 现名/基础名首字母完全，其次首字母前缀。
6. 现名/基础名中文子串。
7. 现名/基础名全拼完全，其次全拼子串。
8. 曾用名首字母完全、首字母前缀、中文子串、全拼完全、全拼子串，按此顺序。
9. 仅状态匹配。

状态分支过滤后按名称片段套用名称排序，与普通分支取较高优先级。同级依次按命中位置靠前、命中键较短、规范代码字典序排列；同码原因再按名称字典序稳定决胜。代码前缀位置统一按去市场前缀的数字串计算。不得依赖接口顺序、价格或随机热度。

默认显示前 **12** 个唯一候选，超出提示“还有更多结果，请继续输入”，首版不分页。完全代码命中第一。`shiyou` 的“必须命中”指完整匹配集合包含目标，不承诺全市场前 12 项必含低优先级旧名；分别验收匹配集合与截断规则，用户可输入更具体旧名定位。

## 3. 交互与添加语义

### 3.1 状态与提交优先级

下拉状态：关闭、加载中、有结果、无结果、字典不可用。加载/提示/错误行不可选择。结果更新重置主动选择，默认预选首个可添加候选，全部已添加则无预选。

Enter 与“+ 添加”共用同一决策入口，依次判断：

| 条件 | 行为 |
| --- | --- |
| IME 组合输入中（isComposing 或兼容保护） | Enter 只确认输入法，不搜索/添加；compositionend 后恢复 |
| 批量模式 | 走批量解析，旧候选不能抢提交 |
| 方向键主动选中了当前有效候选 | 添加指定候选；鼠标/触摸点选也明确指定目标 |
| 输入是完整可解析代码或已有期货别名 | 原路径直接添加，不等待字典，不把前缀候选当完整代码 |
| 下拉打开、查询与输入一致、有可添加候选 | 添加默认预选项，例如 gzmt 后 Enter |
| 其他 | 保留输入，提示加载中/未找到/已在监控/字典不可用，不猜测 |

输入变化立即取消旧查询的提交资格和活动项，不等 150 ms 防抖。任何提交不得使用过期结果。添加成功指进入监控列表及既有持久化流程成功，不等待行情/K 线网络成功。

### 3.2 键盘、指针与添加后行为

- 聚焦且有单项查询时显示；上下键循环可添加项并滚动可见，DOM 焦点留在输入框，关闭时上下键可重开。
- Escape 关闭并清除活动项，同查询迟到结果不能重开。再次编辑、重新聚焦或方向键可打开；Escape 后 Enter 仅代码/批量路径可提交，不能选隐藏候选。
- Tab 正常移焦不添加；焦点离开整个添加组件、点击外部、切换路由时关闭。输入框到同组件按钮的移焦保留本次提交目标，使按钮和 Enter 一致。
- 指针点选在 blur 收起前保存目标，触摸同鼠标，避免 blur/pointer/click 漏加或重复。
- 成功后清空、关闭、恢复输入焦点、反馈新增数量；行情失败保留监控项并沿用行情提示，只有新增代码预热；持久化失败保留输入并报错。
- 已监控候选显示“已添加”、不可提交、键盘跳过；重复添加不刷新/预热。批量反馈新增、重复（列表已有或同批重复）、无效数量，全无效或全重复保留输入。
- 长按 Enter、双击不能产生重复行或重复副作用，提交期间有明确处理状态。

### 3.3 展示与可访问性

- 浮层对齐输入框、高于表格、最大高度滚动、窄屏不超视口；长名可换行/省略且可查看全文，代码与原因清楚。
- 每项显示代码、当前可用名、市场/板块或期货交易所和“连续”标识、有效状态、旧名原因、已添加状态。板块从元数据/项目规则映射，不仅按 sh/sz 猜全部板块。
- 无结果提示“未找到匹配标的，可尝试代码或其他名称”；字典失败提示“名称搜索暂不可用，仍可输入完整代码添加”并可重试；旧版本显示名称数据日期。
- 使用 combobox/listbox/option 和 aria-expanded、aria-controls、aria-activedescendant、aria-selected/aria-disabled；非打断式 live region 播报数量与反馈，状态不只靠颜色。
- 沿用暖米、浅色、深色主题变量，触摸目标至少 44px；标签/占位符提示“代码 / 名称 / 拼音；多代码用逗号或空格分隔”。
- 查询和上游名称以文本节点渲染，高亮不拼未转义 HTML，不将查询当正则。

## 4. 数据契约、来源与维护

### 4.1 最低逻辑契约（待实现）

以下是待实现的逻辑字段约束，压缩格式和文件名在实施时决定，不是当前 API 字段。

| 层级 | 字段 |
| --- | --- |
| 产物 | schemaVersion、version、generatedAt、asOfDate、内容校验值；支持校验/回退 |
| 来源/覆盖 | 来源地址/标识/抓取时间、各市场名单数、别名成功/无历史/失败/未知数量、校对记录；返回空不自动等于无历史 |
| 主记录 | code、type、market/exchange、board、listingStatus、baseName、displayName、名称证据时间及来源 |
| 名称索引 | 原名、类别（现名/基础名/曾用名/维护别名）、首字母、全拼、音节、来源；无证据更名日期为 null |
| 状态层 | flags、observedAt、dateKey、source、freshness（fresh/stale/unknown），独立于长期索引 |
| 结果 | 规范代码、展示字段、最高匹配类别、实际命中名称、排序键、alreadyAdded |

按规范代码关联，同名异码不合并，代码变更不靠相似名称猜关联。停牌/未知不能当退市；明确退市记录不进默认联想，原有完整代码输入按兼容规则处理。

### 4.2 来源与可维护性

构建/维护任务生成静态索引，客户端内存搜索；查询不发第三方，不每敲一个字抓全市场或逐股旧名。

官方文档定义：`stock_info_a_code_name` 提供沪深京代码及简称；`stock_info_change_name(symbol)` 按单股取曾用名；`stock_info_sz_change_name` 是深市更名数据，不能代表三市全量。文档存在不等于部署版本、连通性及历史覆盖已验证。[AKShare 股票数据文档](https://akshare.akfamily.xyz/data/stock/stock.html)

实施前小规模真实验证沪深北样本，记录 AKShare 版本、耗时、失败率、返回字段与关键案例证据；生产数据不能以测试夹具替代，来源及允许使用方式写入产物说明。

1. 全量上市名单为基底；逐股旧名构建限流、断点续跑、记录失败；来源冲突校对，不按列表顺序挑现名。
2. 空/失败/缺页不删除旧别名或判全市场退市，保留最近成功版本；有证据纠正的错别名可删除并留修订记录。
3. 提供可重复生成/校验、增量更新、回滚命令。建议名单及更名每交易日盘后增量、全量旧名每周校核；执行环境与调度在实施时落实，本轮不创建自动任务。
4. 发布逐码比对来源名单，沪深北当前名单缺失为 0 或有明确披露例外，停牌不得例外删除。记录曾用名未知覆盖；关键样例须有证据并通过，不能硬编码几个案例冒充全量。有未知覆盖时仅声明收录范围，不能称完整历史。
5. 通过校验整体切换版本，失败保留旧版，无旧版降级代码；用户配置沿用 storage key，公共字典不无条件写同步 localStorage。
6. 超出计划更新周期未成功则标过期、显示 asOfDate，不以下载时间冒充数据日期；新上市股票由字典更新补齐，空窗期可输代码。

### 4.3 动态快照与时效

- 正确接口 **GET `/api/cache/spot/latest`**。读取 ok、顶层 generatedAt（Unix 毫秒）、stale、ttlMs、source 和 data.items 的 code/name、data.universeComplete。不能直接复用只返回 items 的 `fetchSharedSpot()` 丢失封套证据。
- 仅 ok=true、stale=false、时间有效且不在未来、年龄不超过 ttlMs、同一北京时间自然日时，视为“该快照观察到的当日状态”。ttlMs 缺失/无效则未知；条目自身有更旧日期或 stale 也拒绝其当日状态。
- 同码新有效状态替换旧状态，不累积；有效可识别的无前缀名称可清除旧临时状态。跨日/超时失效，不把昨日 XD 或陈旧 ST 当今日过滤条件。
- 静态基础名始终保留，更新快照可覆盖展示名，截短名不写成基础全名。旧快照不覆盖更新名称证据，历史/最近已知名称不声称实时。
- 缺失项不删除静态股票、不清空为正常状态；universeComplete=false 或缺失则提示覆盖有限，不用部分快照重建全量名单。
- 进入添加组件后台加载一次、合并并发；持续使用最多每 30 秒刷新且不并发，离页停止。内存搜索不等快照，失败下个正常周期或显式重试，不紧密重试。
- 保守时效使状态暂不可搜时提示“当日状态未更新”，代码及基础名搜索继续。旧展示名含状态字符则标“最近已知名称”，不加当前徽标；已打开结果也须在状态到期后更新资格，不只在下次输入检查。
- 完整代码不依赖快照成功，不启动全市场 K 线扫描；GET 快照正常触发的服务端缓存刷新可沿用。

### 4.4 加载、竞态与性能

- 共享字典加载任务和索引实例；首次聚焦异步加载，可空闲预加载。加载期间代码可添加；首次无缓存不承诺离线名称搜索，成功缓存可用版本后才具备离线条件。
- 查询、字典/状态版本和生命周期有归属标识；输入变化、批量、清空、Escape、失焦、切页后旧任务不更新下拉或添加。
- 销毁时清理监听器、定时器和请求订阅；行情刷新不丢失输入、光标或 IME 状态。
- **建议预算（待测）**：压缩字典 ≤ 500 KiB；索引就绪后匹配/去重/排序 p95 ≤ 16 ms；输入结束至首屏渲染 p95 ≤ 200 ms（含 150 ms 防抖，不含首载网络）；索引构建不产生 > 50 ms 主线程任务，必要时分块/Worker。
- 预算替代原稿“几十 KB、< 2 ms、100% 稳定”的无证据保证。报告真实股票/别名数、压缩方式、设备/浏览器/CPU 降速、冷/热加载及至少 1,000 次固定查询；桌面和移动设备分别测。未达标优化或明确修订预算，不能只测演示字典。
