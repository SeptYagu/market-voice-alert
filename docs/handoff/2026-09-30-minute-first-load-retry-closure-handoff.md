## 问题与改动

原分钟刷新计时器只在首次加载成功后安装。首载遇到临时接口故障时，图表进入错误态却没有后续刷新驱动，无法在源恢复后自动重试。

将 `startMinuteRefresh(code)` 从 `loadKline` 的成功路径移到 `finally` 的 `isCurrentTask()` 保护分支。当前分钟图无论加载成功或失败都安装调度器；旧周期、旧实例和关闭后的请求不会安装。既有分钟周期守卫、计时器去重、15 秒限频、自动刷新暂停和销毁清理保持。

## 回归证据

新增失败态单测使用真实生产管理器和请求逻辑，拦截计时器以驱动其实际回调：

1. 周期源与备用源暂时失败，首载显示错误，仍安装一个 15 秒计时器。
2. 自动刷新暂停期间，即使接口恢复，回调不发送请求。
3. 恢复自动刷新后，下一次计时器回调自动重试，清除错误并渲染周期 high=102、low=99、close=101，无需用户操作。
4. 成功重试不重复安装计时器；关闭图表后，已排队的旧回调不发送请求。

该用例在修复前为 0 pass / 1 fail，失败点明确为“首载失败后计时器不存在”；修复后通过。时间由受控回调模拟，没有在单测中真实等待 15 秒。
