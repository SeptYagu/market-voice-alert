## 二、审查发现与缺陷清单

### P2-1 交接期官方柱时效门控对「时效未知/跨日降级」报价不设防：东财兜底通道的盘前滞后快照仍可污染已确立官方柱 open/low，低点全天锁死且无自愈路径（R11 P2-1 残留半程，验收标准 1 仍被旁路）

- **严重级别**：P2（与 R8 P2-1 同族同impact、与 R11 P2-1 同一缺陷路径——本轮修复只闭合了「时间戳存在且 < 09:25」的子形态；特定场景下核心功能错误、当日不可自愈）。
- **文件与行号**：`src/js/kline.js:709-724`（原地分支 `else` 路径非连续交易时段）；关联判据 `:710-711`（`isPreOpenStale = quoteTimeMinutes !== null && quoteTimeMinutes < 9*60+25`）与 `:725`（`if (quoteOpen) updated.open = quoteOpen`）。
- **触发条件**（三个前提同时成立）：
  1. 当日官方柱已确立（`last.preview` 为 false，如 09:25:03 携带官方时间戳的腾讯快照落柱，或 `fetchKline` 重载后合并确立）；
  2. 随后一拍快照**时效未知**（`quoteTimeMinutes === null`）或**跨日时间戳被降级为 null**（`getQuoteBeijingTimeMinutes` 对 `digits.slice(0,8) !== targetDate` 返回 null，`kline.js:462-467`）——即东财兜底报价通道（`parseEastmoney` 无 `updateTime`/`time` 字段，`parser.js:299-319`；`api.js:211-222` 对腾讯缺失代码逐码回落东财，混合源场景真实存在）；
  3. 到达时客户端时钟处于 09:25-09:30（`isContinuousTrading === false`），且该快照为盘前滞后数据（如 09:24 前抓取、延迟入缓存的东财快照，`price` 为未撮合虚拟价）。
- **实际行为与期望行为**：
  - 实测（本轮独立探针，真实模块、仓库内临时脚本 `tmp-round12-verify.mjs`，已删除；输出摘要）：
    - **N1**：09:25:03 官方柱确立（`o=l=20.5, v=90000`）→ 09:27:00 到达无时间戳快照 `{price:19.6, open:0}` ⇒ 官方柱变为 `{low:19.6, close:19.6}`（`open` 幸存于 open=0，`low`/`close` 被污染）；
    - **N1b**：同场景快照携带非零指示性 `open:19.6` ⇒ 官方柱变为 `{open:19.6, low:19.6, close:19.6}`——**下影线重现**；
    - **N1 日终推进**：14:55 真实成交（`low:20.3`）⇒ 全天柱 `low=19.6`（真实最低 20.3），低点被虚拟价锁死全天。
  - 期望：官方柱在 09:25-09:30 交接期内对「时效未知」报价与 preview 分支/追加分支保持同等 Fail-Closed 口径——不动官方柱 `open`/`low`/`high` 极值（R11 修复建议原文即为此口径：「不动官方柱极值，仅 close 随现价」）。
- **根因**：本轮落地的时间戳门控判据是合取式 `quoteTimeMinutes !== null && quoteTimeMinutes < 09:25`——它只能识别「时效实锤为盘前」的快照；对 `quoteTimeMinutes === null`（东财兜底无时间戳、跨日时间戳降级）走 `else` 放行路径，按「最新报价」吸收极值。该取舍虽已在代码注释（`:719-721`）与 STATUS 登记，但其登记依据「按最新报价吸收极值与成交量，确保真实盘中推进兼容」隐含了「快照是新鲜的」这一**对无时间戳报价不可验证的假设**——与 R8 P2-1 被证伪的「内容代理判据」共享同一错误假设；且与同文件 preview 分支（`:688-700`：时效未知 ⇒ 坍缩滞留）及追加分支（`:589-611`：时效未知 ⇒ preview 柱）的 Fail-Closed 口径自相矛盾，防护矩阵第三条路径形成结构性缺口。
- **影响范围**：A 股日K（`1d`），仅限「腾讯主源间歇缺失该代码 → 东财兜底补位」或跨日时间戳降级的代码。污染不可自愈：① `low` 锁死全天（连续竞价分支 `low = min(lastLow, quoteLow, price)` 恒 ≤19.6）；② `refreshPreviewKline`（`chartRowController.js:550-575`）以 `last.preview` 为前置门禁，官方柱被污染后**永不触发**强制重载；仅手动切周期/强刷可恢复。
- **复现方法 / 验证证据**：上述 N1/N1b/N1-日终三步序列可直接复现（逐拍调用真实 `applyLiveQuoteToKline(items, quote, '1d', 'sh603533', now)`）。测试覆盖缺口证实：`tests/callAuction.test.js` 全部 37 条用例中，「无时间戳快照」负例（1p/1s/1t/1u/1v/1w）的前置均为 **preview 柱或追加分支**，「官方柱 + 时效未知快照 @09:25-09:30」**零用例覆盖、零变异判别力**——R11 修复验收第 3 条「登记未知时效取舍」若采纳非 Fail-Closed 口径须补对应负例，本轮未补。
- **修复建议**：将 `:711` 判据改为 Fail-Closed 极性——`const quoteKnownStale = quoteTimeMinutes === null || quoteTimeMinutes < 9 * 60 + 25;`，交接期（`!isContinuousTrading`）内该判据为真时跳过对官方柱 `open`/`high`/`low`/`volume`/`amount` 的写入（可保留 `close` 随现价或整拍 `return items`，二选一须登记）；同时 `:725` 的 `quoteOpen` 覆写须纳入同一门控。若坚持现行为，须给出「官方柱 + 时效未知快照」在 09:26-09:29 不被污染的替代机制并补负例。
