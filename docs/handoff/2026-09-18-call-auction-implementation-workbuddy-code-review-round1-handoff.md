### P1-1 09:25 交接未清除盘前预览极值：日K 虚假下影线仍然形成并被锁死整个交易日

- **严重级别**：P1
- **文件与行号**：`src/js/kline.js:543-552`（`period === '1d' && isAStock` 的**原地更新**分支：`updated.high = Math.max(lastHigh, price)` / `updated.low = Math.min(lastLow, price)`）；来源侧 `src/js/kline.js:476-505`（09:25 前守卫把「临时预览柱」直接写进 `items`，`open=high=low=close=price`，无任何来源标记）；同根因另一入口 `src/js/kline.js:507-524`（≥09:25 追加分支无条件信任 `last` 为官方柱）。
- **触发条件**：A 股（`inferAssetType(code) === STOCK_CN`）+ `period === '1d'` + 图表在 09:15-09:25 期间处于展开状态（`loadKline` 已把当日官方柱之前的序列载入内存），且 **09:24:xx 最后一拍盘前虚拟撮合价 < 09:25 正式撮合开盘价**（即最后一拍未被随后的真实最低成交价覆盖）。
- **实际行为**：09:25 之后守卫失效，代码走入 `:543-552`，把守卫 1 秒前写入 `items` 的**盘前虚拟预览柱**当作权威官方柱做 `Math.min(lastLow, price)`，于是盘前虚拟价成为当日 low 并因单调 `min` **不可逆锁死**；官方日K 的 `fetchKline` 只在展开图表/切周期/强制刷新时发生（`chartRowController.js:354-428`，全仓无周期刷新），故该假下影线持续整个交易日。
- **期望行为**：09:25:00 起当日柱的 high/low 必须只由**真实成交价突破**驱动（`price > last.high → high=price`、`price < last.low → low=price`）；09:18-09:24 的虚拟撮合价（含最后一拍）绝不进入当日柱任何价格字段。
- **根因**：预览柱与官方柱在 `items` 中**同形无标识**，`≥09:25` 分支的「官方柱具有最高权威，仅由真实成交突破驱动」这一前提在「守卫刚创建/改写过的预览柱」上不成立——即设计 §3.1.3 的极值驱动规则与 §3.1.2 的预览柱写入之间缺少交接重基线（re-base）步骤。
- **影响范围**：需求 1 覆盖的主场景（盘前打开图表盯集合竞价并保持到盘中）当日日K 恒带虚假下影线，污染 MA/形态识别；非 A 股不受影响（已验证）。
- **复现方法/运行证据**（生产入口 + 冻结墙钟，`ChartRowManager.applyLiveTick('sh603533', quoteWithDate)`，`items` 末柱为上一交易日；真实时钟经 `Date` 替身冻结，`applyLiveQuoteToKline` 未显式传 `now`，与该函数生产默认行为一致）：

  | 时刻 | 报价（虚拟/真实） | 输出末柱 open/high/low/close |
  |---|---|---|
  | 09:18:00 | price 18.00（极端申报压跌停） | 18 / 18 / **18** / 18 |
  | 09:20:00 | price 18.60（撤单回弹） | 18.6 / 18.6 / **18.6** / 18.6 |
  | 09:24:50 | price 19.60（盘前最后一拍虚拟撮合价） | 19.6 / 19.6 / **19.6** / 19.6 |
  | 09:25:03 | price 20.50（**正式撮合开盘**） | 20.5 / 20.5 / **19.6** / 20.5 |
  | 10:00:00 | price 20.90 | 20.5 / 20.9 / **19.6** / 20.9 |
  | 14:55:00 | price 21.30 | 20.5 / 21.3 / **19.6** / 21.3 |

  3. 任选其一，均需同时在 `:507-524` 追加分支落同一语义。
- **修复后验收标准**：
  1. 上表序列 09:25:03 起 `low === 20.50`（真实最低成交价），且全天任何后续 tick 均不得回升到 19.60/19.00；

  3. 非 A 股 5 类样本零回归（09:24:59 `high=103/low=98` 保持）；`npm test` 全绿。

### P2-2 修复仅覆盖 `period === '1d'`：周K/月K 在集合竞价期间仍被外部脏 `quote.low` 不可逆写死

- **严重级别**：P2（与 Bug 1 同根因，属修复范围遗漏；任务书验收标准 1 只声明日K，故不按 P1 定级）

- **修复后验收标准**：上述两行实跑 `low === 21`（官方周K 最低）且 10:00 后不回弹；新增 `1w`/`1M` 盘前用例；`1d` 与非 A 股既有断言不转红。

## 三、待确认风险与未验证项

1. **上游 09:26-09:29 分时点与网格缺槽**：`_isTradingSessionTime` 的 A 股区间仍为 `[[555,690],[780,900]]`（09:15-11:30 连续放行），而 253 固定网格无 09:26-09:29 槽位（设计 §3.2.2 有意不补空白分钟）。若上游 1m K 线或共享缓存返回该窗口的点，`setData` 侧会因 `displayTimes` 无对应槽位而**静默丢弃**（不显示、不报错）。本环境离线无真实样本可证，未验证。
2. **`_isTradingMinute` 扩至 09:15-09:25 对港股/美股的连带依赖**：已验证客户端 `_isTradingSessionTime` 与服务端 `server/intradayService.js:44-46` 均按策略区间过滤（港股 `[570,720]/[781,960]`、美股 `[1290,1440]/[0,240]`），故港股/美股序列不含 09:15-09:25 点 → 本轮零回归成立（我的 09:16 单测仅证明「若存在该点会被追加/丢弃」）。但该结论**依赖过滤链完整**：一旦某数据源绕过过滤（例如共享缓存返回未过滤数据），`hasNonStockHours` 下界收窄至 09:15 会让港股的 09:15-09:25 点既被追加又无槽位显示。建议补一条「非 A 股 09:16 点」守护用例固化该前提。
3. **守卫的「钳位」分支无日期校验**：`kline.js:495-503` 在 `lastDate < targetDate` 不成立时无条件钳位 `items` 末柱，未校验 `lastDate === targetDate`。当报价的 `targetDate` 解析为上一交易日（非交易日/日历未就绪时 `resolveLiveFallbackDate` 回退）时，会把**已收盘的上一交易日柱整体压成 `price`**（open=high=low=close）。当前自动刷新在 `closed` 会话被 `isAutoRefreshAllowedInSession` 关断（`app.js:1223`），自动路径未证实可达；手工刷新或后续门禁改动后需重新评估。建议在钳位前加 `lastDate === targetDate` 判定。
4. **语音「严格按 interval 保证播报」的既有边界**（继承设计阶段登记限制，本轮未改动）：09:20-09:25 的保证落在「每拍调用一次全量 `speech.speak`」，若 TTS 后端按 code 合并/丢弃排队项，则听感层面的绝对保证仍取决于语音适配器；另 09:20 起定时器由 30s `checker` 触发的 `startTimer()` 启动（`voiceController.js:77-101`，含 `memory.clear()`），最坏会有 <30s 的启动延迟，语义正确但首拍时刻非 09:20:00 整。

## 四、推荐修复顺序与复审验收标准

1. **P1-1（阻断项）**：09:25 交接重基线（预览柱加来源标记 → ≥09:25 首次重基线为真实值），追加分支同语义；验收见 P1-1 §修复后验收标准 1-3。
2. **P2-1**：补齐判别性用例（盘前价 ≠ 开盘价、盘前报价带虚拟 high/low）+ M2 定点变异实跑转红；与 P1-1 同批提交。
