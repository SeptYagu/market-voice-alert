### P2-4 会话策略缺少“代码→策略”分派契约；既有单例全局会话与语音调度状态机是真实污染点

- **触发条件**：添加恒指期货并触发语音播报；或按 §1.2 目标核查路线图。
- **实际行为**：实测 `hf_HSI` = 恒生指数期货，报价有效（`24716.200`，持仓量 136902），以**港币**计价；但方案 §3.4 按资产类型推断货币，`futures_global` 一律输出“美元”；同时 §4 路线图 Phase 1/2/3 均未安排恒指期货。
- **期望行为**：货币单位按品种元数据而非资产类型；§1.2 的目标品种在路线图中有明确归属。
- **根因**：货币与资产类型被错误地做成了一对一映射，忽略了 `futures_global` 内混合计价币种（CME=USD、HKFE=HKD、SGX A50=USD）。
- **影响范围**：恒指期货播报币种错误；§1.2 目标与 §4 路线图不一致。
- **复现方法/证据**：现场请求 `hf_HSI` 返回完整 15 字段（品种名“恒生指数期货”）；`getVoiceEligibleCodes`/TTS 货币判定的入参只有 `asset_type`（方案 :120-123）。
- **修复建议**：在品种元数据中增加 `currency` 字段（`USD`/`HKD`/`CNY`），TTS 按该字段取词；路线图补入恒指期货的 Phase 归属。
- **修复后验收标准**：恒指期货播报“港币”、其余外盘播报“美元”；存在按品种断言货币的用例；路线图覆盖 §1.2 全部目标品种。

### P3-3 性能红线自相矛盾，不可作为可验收门禁

- **文件与行号**：`:177-178`
- **触发条件**：以 §5.3 作为下一阶段验收判据。
- **实际行为**：`:177` 同时给出“**不因新增资产词典发生显著膨胀**”与“**词库增量控制在 < 150KB**”两条语义冲突的判据。当前生产包实测 `dist/assets/index-*.js` = **375,679 B**（约 367KB，已内联 469KB 的 `src/data/stock-suggest-dictionary.json`），150KB 增量 ≈ 现值 **+41%**，不能被判定为“不显著”。
- **期望行为**：门禁为单一、可测量、可判定的指标。
- **根因**：以“增量绝对值”与“相对膨胀可接受度”混用作为同一红线。
- **影响范围**：下一阶段的性能门禁无法客观判定（既可通过也可不通过）。
- **复现方法/证据**：`ls -l dist/assets/` 实测 375,679 B；`wc -c src/data/stock-suggest-dictionary.json` 实测 469,261 B。
- **修复建议**：改为单一指标，例如“gzip 后总包体 ≤ 现值 + X%”或“词库增量 ≤ 现有词库的 Y%”，并注明测量方式（build 产物 / gzip）。

### P3-4 §2.1 结论“持仓量字段完备”不适用于 Phase 1 全部品种

- **文件与行号**：`:50-52`、`:158-159`
- **触发条件**：在 Phase 1 品种上展示持仓量。
- **实际行为**：新浪 `hf_` payload index 9 即持仓量。现场实测 `hf_CL`/`hf_GC`/`hf_SI`/`hf_HG`/`hf_NG`/`hf_NQ`/`hf_ES`/`hf_YM` 的 index 9 **恒为 0**；非 0 仅出现在 `hf_CHA50CFD`（805079）与 `hf_HSI`（136902）。而 Phase 1 清单（:158-159）除 A50 外全为 CME/ICE 品种。
