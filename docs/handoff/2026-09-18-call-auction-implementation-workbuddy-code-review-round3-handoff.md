## 二、审查发现与缺陷清单

### P2-1 09:25 交接防抖判据不健全：滞后快照只要"价格未回落"或"携带非零 open"，盘前虚拟价仍被重基线固化并全天锁死

- **严重级别**：P2
- **文件与行号**：`src/js/kline.js:585-596`（判据在 `:588`、重基线 `:590-593`、清除标记 `:594-595`）；上游预览柱来源 `:484-499`（追加路径）与 `:504-517`（原地路径）；清除后的永久接管分支 `:583` + `:597-603`（`else` 的 `Math.min(lastLow, price)`）。
- **触发条件**：A 股 + `period === '1d'` + 09:15:00–09:24:59 期间图表展开并已写入盘前预览柱（`preview:true`，价格即盘前虚拟价），其后 **09:25 首拍为滞后快照**（仍为盘前数据），且满足以下任一：
  1. 快照携带非零 `open`（竞价虚拟开盘价）→ `!quoteOpen` 为假（`:588` 第一合取项失守）；
  2. 快照价格已推进到新的盘前虚拟价（≠ 上一拍预览价）→ `price === last.close` 为假（第二合取项失守）；
  3. 上游滞后延续到 09:30:00 及以后 → `min < 9 * 60 + 30` 整体失效，判据不再具备"保留预览"的能力。
  以上三种均被判为"新鲜"，于是 `:589` 的 `if (!isStillStalePreOpen)` 进入重基线：`open = quoteOpen || price`、`high = Math.max(open, price)`、`low = Math.min(open, price)`，并 `delete updated.preview`——`preview` 是一次性开关，清除后 `:597` 的 `else` 分支永久接管，盘前虚拟价随即成为 `last.low` 并被单调 `Math.min` 锁死。
- **实际行为与期望行为**（真实盘面：开盘 20.50、盘中最低成交 20.50；盘前最后一拍虚拟价 19.60）：

  ```

    09:25:00 price=19.60 open=19.60 -> 19.6/19.6/19.6/19.6  (preview 被清除，重基线到虚拟价)
    09:25:05 price=20.50 open=20.50 -> 20.5/20.5/19.6/20.5
    14:55:00 price=21.30 open=20.50 -> 20.5/21.3/19.6/21.3   ← low 全天 19.60（虚假下影线 0.90）

  C3b (滞后快照价格已推进，无 open)
    09:24:50 price=19.60 open=19.60 -> 19.6/19.6/19.6/19.6 preview=true
    09:25:02 price=19.80 (无 open)   -> 19.8/19.8/19.8/19.8  (判为新鲜，重基线)
    09:25:32 price=20.50 open=20.50 -> 20.5/20.5/19.8/20.5
    14:55:00 price=21.30 open=20.50 -> 20.5/21.3/19.8/21.3   ← low 全天 19.80

    09:24:50 / 09:25:00 / 09:29:59 price=19.60 (无 open) -> 19.6 且 preview=true（保留，正确）
    09:30:00 price=19.60 (无 open)   -> 19.6/19.6/19.6/19.6  ← min<09:30 失效，判据整体关闭
    09:30:30 price=20.50 open=20.50 -> 20.5/20.5/19.6/20.5
    14:55:00 price=21.30 open=20.50 -> 20.5/21.3/19.6/21.3   ← low 全天 19.60
  ```

  期望行为（验收标准 1「日K集合竞价下影线彻底消除」）：09:25:00 起当日柱的 `high/low` 只能由**真实成交价突破**驱动，任何盘前虚拟价（含首拍虚拟撮合价）不得进入当日柱任何价格字段。C2/C3b/C4 的 `low` 均应恒为 20.50。
- **根因**：`isStillStalePreOpen`（`:588`）用「价格与上一拍预览价相等」+「无 `open`」两个**内容特征**去近似"快照仍处盘前态"，这是对上游时效的**代理判据**而非时效判据本身——它只能识别"payload 与上一拍逐字段不变"这一种滞后形态；一旦滞后快照的价格推进（竞价虚拟价在 09:25 前本就持续变动）或携带虚拟 `open`，判据立即误判为新鲜。且 `preview` 是**一次性**状态：`:589` 分支一旦执行重基线，`:594-595` 即永久删除标记，后续真实开盘价只能走 `:597-603` 的 `Math.min(lastLow, price)`（被污染的 `last.low`），不可逆。

- **复现方法 / 运行证据**：
  1. 仓库外探针 `_probe_r3b.mjs`（C2 见 `== C2 ==` 输出，C3b 见 `== C3b ==`）、`_probe_r3c.mjs`（C4），均为 `applyLiveQuoteToKline(items, quote, '1d', 'sh603533', new Date(...))` 逐拍调用，输入与生产入口同形（`applyLiveTick` 在报价缺 `date` 时补 `date=today`，与探针显式传 `tradingDay` 等价）。
  2. 生产可达性：`app.js:1359 → applyLiveTickToChartForCode:1320 → chartRowController.applyLiveTick:543 → applyLiveTickToKlineChart:116 → applyLiveQuoteToKline:456`，`now`/`effectiveCode` 转发链本轮已接通（实测 `inst.klineData.code='sh603519'` 归一化后 `inferAssetType` 命中 `STOCK_CN`）；自动刷新在盘前可经 `app.js:1218` 的期货开市豁免放行（Round 2 已实测 `isFuturesMarketOpen(AU0/RB0)` 在北京 02:00/09:05 均为 `true`），另有工具栏手动刷新与启动期 `refreshNow()`。

- **修复建议**（任选其一，均需移除 `preview` 的一次性不可逆性）：
  1. **优先**：把"是否可清除 preview"挂钩上游时效，而非内容特征——要求快照自带可比时间戳（`updateTime`/`quoteDate`/`tradingDay` 或服务端发布时刻）晚于 09:25:00 才允许重基线，否则保持 `preview` 直到官方日K重载；
